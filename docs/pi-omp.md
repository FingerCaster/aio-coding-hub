# Pi / OMP 原生配置与 AIO 网关

Pi 和 Oh My Pi（OMP）各有独立供应商入口，页面分为“原生配置”和“AIO 网关”。原生供应商与 AIO 生成入口可以同时存在；请在 CLI 的模型选择器中主动选择要使用的供应商和模型。AIO 应用入口不会改写默认模型，也不会切换已经运行的会话。

## 配置原生供应商

1. 打开“供应商”，选择 Pi 或 OMP，再选择“原生配置”。
2. 核对配置目标，可使用默认目录、自定义 agent 目录或 OMP profile。以页面展示的实际文件路径为准；桌面应用的环境不一定等同终端环境。
3. 新增或编辑供应商及模型。“已加入”表示当前目标文件中存在这个显式节点，不表示它是默认模型或当前会话正在使用它。
4. “移除”从原生文件移除节点并保留档案；保留的档案可再次应用。“删除档案”另有确认。
5. 外部编辑原生配置后刷新页面。编辑或确认期间文件发生变化时，需要重新加载，避免覆盖他人的修改。

供应商列表支持按名称或标识搜索，以及按“全部 / 已加入 / 未加入”筛选。原生配置和 AIO 网关仍为两个独立视图；从 CLI 管理直达时会保留所选配置目标。

默认配置通常是 Pi 的 `~/.pi/agent/models.json` 与 OMP 的 `~/.omp/agent/models.yml`。OMP 的环境目录、profile 和 `.yaml` 后备由目标解析器处理；旧 JSON 仅供读取，应先通过 OMP 自身完成迁移。

编辑会保留未知字段和其他供应商节点的语义，但可能重排格式、移除注释。写入前建立私有原文备份。无法安全解析的文件进入只读或错误状态，不会按空文件覆盖；有歧义的 YAML（如重复 key、锚点和 merge）不能直接编辑。

## 配置 AIO 网关

1. 在“AIO 网关”中添加上游，或从原生供应商使用“添加到 AIO 网关”查看导入预览。
2. 明确填写网关上游 API Key，选择协议并补全模型能力。原生环境变量、命令表达式和登录凭证不会作为网关密钥执行或读取。导入的上游初始为停用状态。
3. 启用上游并确保 AIO 本地监听器运行。模型声明需包含准确的输入类型、上下文与输出上限、工具和思考能力。
4. 在“独立 AIO 入口”预览目标文件、协议、URL 与发布模型，确认后应用。每个协议生成一个独立节点，最多四个。
5. 在 Pi / OMP 选择 `aio-coding-hub-<协议>` 中的模型。之后在日志、用量页面按 Pi / OMP 查看实际请求。

支持的 HTTP/SSE 协议：

| 原生 api | 网关用途 |
| --- | --- |
| `anthropic-messages` | Anthropic Messages |
| `openai-completions` | OpenAI Chat Completions |
| `openai-responses` | OpenAI Responses |
| `google-generative-ai` | Google Generative AI |

同协议、同模型且能力兼容的上游可按现有路由策略重试和失败切换。不兼容协议不会被当作备用上游尝试。生成节点只含本地网关地址、占位凭证和明确的模型能力，不复制真实上游密钥或可能绕过网关的配置。

原生导入是独立快照，后续刷新原生配置不会更新网关上游。修改上游、模型能力、路由策略或端口后，应重新预览并应用入口；新上游不能在目录未更新时降低已发布模型的能力。

## 从 AIO 统一渠道接入

在 Pi / OMP 的原生供应商页或 AIO 网关页，点击“从 AIO 渠道接入”。选择当前目录 / Profile 下需要接入的来源和模型，预览后确认。可同时接入 Claude Code、Codex、Grok 和 Gemini；Grok 的 Chat Completions 与 Responses 是两个独立入口。

请求路径为 `Pi / OMP → AIO 聚合网关 → 渠道可用上游`。每个渠道与协议对应一个 AIO 本地入口；“AIO 调度池”展示候选上游及准入状态，实际请求再按模型、协议、额度与健康状态筛选，并遵循该渠道的选源和重试规则。候选通过准入不代表能够处理所有模型。

来源供应商需要先声明该 Pi / OMP 消费端对应协议的模型能力，包括输入类型、上下文、输出上限、工具与推理支持。模型 ID 或名称不代表能力证据。缺少声明时在弹窗中补齐；没有合格候选时会显示阻塞原因。

生成节点为 `aio-channel-<来源>-<协议>`，显示名称为“AIO · 来源”。它实时引用来源当前启用的供应商池、排序、认证与模型路由，不复制上游或真实密钥。后续请求按来源当前候选调度，并再次核对已发布模型能力。新增模型需要更新入口，来源配置发生实质变化时需要重新确认能力。凭证轮换不需要把新密钥写入原生配置。

在 Pi / OMP 自身的模型选择器中选择该入口即可使用。接入不替换默认模型，不影响已运行会话。日志保留 Pi / OMP 调用方，并显示来源渠道和实际上游，例如“Pi → Codex”；一次请求仍只走一套统计。

再次打开“更新”可调整已发布模型。一次发布中没有选择的渠道保持不变；“撤回”只删除当前目标中对应且未被外部修改的托管节点。来源供应商、其他入口和原生节点均保留。预览、取消或切换目标不会自动写配置。

### 自动获取模型与能力

在“从 AIO 渠道接入”中展开“AIO 调度池”，选择“维护模型资料”。这些资料是 AIO 筛选可用上游的能力依据，接入仍指向同一个渠道聚合入口。编辑器会自动读取上游模型目录，并复用来源中明确保存的上下文与思考等级。

模型列表支持搜索、多选、全选当前结果和一次批量添加。已知的上下文、最大输出、输入类型、工具与推理支持、思考等级会自动填入。完整模型以摘要展示，展开“修改模型参数”即可逐项调整。Pi 的档位映射，以及 OMP 的思考模式、等级映射、默认等级等均可通过下拉配置；常规配置无需手写 JSON。自定义模型 ID 和高级 JSON 仍可使用。

仅提供模型 ID 时，会按来源、认证类型、协议和精确 ID 匹配内置的 Pi 0.87.1 / OMP 18.3.2 模型目录，补齐可识别模型的默认参数。来源明确配置和上游返回值优先；内置目录是可编辑的参考默认值，不代表上游实时承诺。OMP 默认思考等级优先采用来源明确值，再选 medium、low 或首个支持等级；Pi 使用原生档位映射，不改全局默认模型或会话。未知、自定义别名或不匹配协议的必填项仍显示待补充。遇到 AIO 模型/思考路由改写或上游能力冲突时，需要核对实际路由后的能力。

“刷新模型与能力”保留手动修改和已保存声明。获取失败也保留已有候选与草稿；关闭窗口或切换目标后，旧响应不会回填新窗口。只有点击“保存模型声明”，再按接入流程预览并确认发布，才会修改保存的声明和原生入口。

### Gemini 的支持边界

Gemini 标准 `google-generative-ai` API 是本期接入路径。Google 的个人旧 Code Assist / Pro / Ultra CLI 服务于 2026-06-18 迁往 Antigravity，并不意味着 Gemini API 整体退役。当前 AIO 未保存可验证的企业许可证据，因此新渠道接入中的 Gemini OAuth 会显示“需核实企业许可及适配”，不能只凭旧 token 放行；也不提供 Antigravity 来源或自动迁移按钮。

Claude / Codex / Grok 的来源 OAuth 复用 AIO 公共适配器。开发验证采用本地模拟凭证和服务；这不等同于真实账号许可或在线服务验收。上述限制仅作用于新接入流程，不改写已有来源账号。

## 状态与撤回

- “已配置”仅表示入口节点已写入；监听器就绪和实际观测到请求分别展示。
- “配置待刷新”表示目录或路由发生变化，需要重新预览。
- “配置被外部修改”表示托管节点不再匹配记录，AIO 会阻止覆盖或删除。保留文件备份，并核对手工修改后再处理。
- “预览移除入口”只撤回当前仍由 AIO 管理且内容未改的节点，保留原生供应商、网关上游档案及默认设置。如果你曾手工把 AIO 模型设为默认，请自行选择新的默认。

## CLI 管理

在“CLI 管理”选择 Pi 或 OMP，可查看安装状态、版本、可执行文件、模型配置路径和 Shell 解析方式。路径过长时可悬停查看全文，也可复制路径或打开当前配置目录。

“切换目录”复用供应商页的目标校验；OMP 另可选择 Profile。“管理原生供应商”和“管理 AIO 网关”分别直达对应视图。

### OMP 原生设置与 Agent

OMP 的 CLI 管理页提供“模型与会话 / 子任务行为 / Agent 配置”三组设置，保存到当前选中的全局或 Profile 目录。优先使用 `config.yml`，已存在 `config.yaml` 时原位更新；旧 `settings.json` 只读，请先使用 OMP 完成迁移。

- **模型与会话**：设置默认模型、默认思考等级、内置和自定义模型角色、工具审批、消息处理和上下文压缩。默认模型写入 OMP 的 `modelRoles.default`，角色可由 Agent 通过 `@角色名` 引用。
- **模型选择**：显示当前原生模型文件中的供应商和已发布 AIO 聚合入口，并补充 OMP 18.3.2 内置目录。支持搜索、下拉选择、手动选择器和思考等级后缀。目录存在不代表账号已登录，也不保证上游可用；未列出的已有值不会被自动清除。
- **子任务行为**：设置并发数、递归层数、运行和空闲时限、请求预算、思考上限、LSP、委派倾向、批量任务以及隔离工作区。选择“继承默认”或清空数值会移除显式字段，交给 OMP 当前版本决定默认值。
- **Agent 配置**：显示内置 Agent、所选目录 `agents/*.md` 中的自定义 Agent，以及已配置但定义未发现的 Agent。可逐个启停、指定模型/角色与思考等级、配置首次编辑交接（prewalk）、顾问（advisor）和服务等级。保留其他 Agent 的配置及已有模型回退列表。
- **自定义 Agent**：可以新建或编辑原生 Markdown 定义，包括工具列表、允许派生的 Agent、模型、思考等级与系统提示词；高级 frontmatter 随原文保留。同名自定义 Agent 可覆盖内置定义；项目和插件定义仍由原来源管理，本页不执行插件发现。

仅点击“保存 OMP 设置”或“保存 Agent 定义”才写入。只更新改动字段；原始文件会备份到相邻 `.aio-native-backups`，YAML 排版可能规范化。文件被 OMP/编辑器修改、文件优先级变化或目标切换后，旧修订保存会被拒绝，表单草稿保留以便核对。损坏文件、重复 YAML 键、特殊引用和链接文件不会被当作空文件覆盖。

本页展示持久化全局/Profile 值，不是某个项目或运行中会话的完整有效配置。项目设置、环境变量和启动参数可能覆盖它们；默认模型用于后续新会话。`modelRoleStorage=project` 影响 OMP 自身模型选择器的写入位置，本页仍只编辑显示的全局/Profile 文件。供应商导入与 AIO 入口发布仍不会自动改变默认模型。

“版本管理”在进入页面时检查最新稳定版本；页面处于前台时每小时复查，也可点击“检查更新”。检查只读取官方版本和校验元数据，不下载程序，不安装或升级。

未安装时可点“下载安装”，存在更新时可点“一键升级”。确认窗口展示 CLI、固定目标版本、安装方式和目录；确认后才下载并安装。Pi 使用已识别的 npm prefix 或 Bun 目录，OMP 支持 Bun 与官方独立程序；无法确认来源的脚本、开发版或其他包管理器保持手动管理，不会悄悄安装另一份。

旧 Pi 包 @mariozechner/pi-coding-agent 已停用，页面与维护中的 @earendil-works/pi-coding-agent 比较最新版本，并提示手动迁移；不会将旧包的最后版本误报为 Pi 最新版。

OMP 独立版从官方 Release 下载当前平台程序，核对 SHA256 与实际版本后原子替换。下载、校验失败保留原程序；Windows 文件被占用时请退出 OMP 再重试。安装计划短期有效且只能执行一次，安装状态变化或多个升级同时运行时会拒绝执行并提示重新检查。安装成功刷新状态，重新打开 CLI 会话使用新版本。Windows 安装会补充用户 PATH；macOS / Linux 需确认展示的安装目录在 PATH 中。

“安装与更新”仍提供官方命令复制、文档和发布页入口；未检测到 CLI 时自动展开。版本检测优先读取已知 npm/Bun 包元数据；OMP 独立程序则在临时配置目录和清空继承环境后运行限时 --version 查询，不读取日常 agent 配置、凭证或扩展。查询失败时仍显示“已安装 · 版本未知”，不声称已是最新，可在终端确认。

## 当前边界

CLI 管理会自动检查版本，但只在用户点击并确认后执行下载安装或升级，不会自动升级，也不会启动交互会话。仅 OMP 独立程序允许隔离的非交互版本查询。Pi / OMP 的原生 OAuth、特殊云认证、WebSocket、扩展协议，以及 MCP / Skills / Prompts / 会话、WSL 管理不在本次接入范围。

Pi / OMP 的分享和全量配置包迁移暂不支持新增的协议、模型及节点所有权语义，操作会明确拒绝，避免静默丢字段；设备本地的配置目标不会随配置包迁移。存在 Pi / OMP 网关上游、入口 manifest、统一渠道绑定或其能力声明时，旧格式全量配置包导出和替换导入均被阻止。

本次验证使用固定 Pi 0.87.1 与 OMP 18.3.2，在 Windows 隔离环境运行。macOS / Linux 的新增路径与权限行为没有本轮实机验收证据；其他 CLI 版本仍需针对其配置与协议变化验证。

2026-09-26 另核实上述两个版本仍为最新稳定版，并完成本机安装版验收：Pi 通过全局 npm 包升级，OMP 使用官方 Windows x64 独立可执行文件。两款实际安装入口经 AIO 的八条链路、80 项增强协议测试、23 项配置测试均通过。安装操作由本次开发任务执行，不属于 AIO 的自动安装功能。2026-09-27 修复 OMP 独立程序的版本读取，并补充 Windows 官方默认安装目录扫描，覆盖 AIO 启动后用户 PATH 更新尚未被当前进程继承的情况。

### 查看 OMP 继承模型

OMP 原生设置中的继承选项会显示当前配置可以解析出的模型名称，下方列出完整模型标识、继承路径和思考设置。例如快速角色继承默认角色时，会显示该默认模型以及 `@smol → @default`。修改尚未保存的默认模型后，预览同步更新；继承本身不会写入固定模型。

“配置解析”展示所选全局/Profile 配置与当前草稿，不代表检测了运行中会话。未固定模型、候选回退列表、自动选择和父会话继承会说明具体原因；最终模型可能取决于认证、项目覆盖和启动时的会话状态。
