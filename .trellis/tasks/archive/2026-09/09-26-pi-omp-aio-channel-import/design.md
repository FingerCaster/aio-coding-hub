# Pi / OMP 接入 AIO 统一渠道：实施设计

状态：用户已批准，实施中。本文描述实现契约；测试证据另见 research/validation.md。

## 1. 用户流程

1. 供应商 → Pi / OMP → 当前配置目录，点击“从 AIO 渠道接入”。AIO 网关视图提供同一入口。
2. 弹窗展示 Claude Code、Codex、Grok、Gemini 渠道卡片。每张卡片展示来源、协议、认证资格过滤后的候选数量、已有绑定和阻塞原因；不显示上游凭证。Gemini 的 API、企业 OAuth、退役/待核实 OAuth 有独立原因，不能只显示笼统“Gemini 不受支持”。
3. 勾选一个或多个渠道，选择对应显式模型。工具、输入类型、上下文、输出上限、推理等能力缺失时，在同流程补齐有依据的声明。
4. 预览“将添加/更新的供应商 + 模型 + 目标文件”。对同名节点、只读文件、源版本变化和旧绑定分别提示。
5. 确认后在原生配置中生成独立 AIO 托管节点。用户在 Pi/OMP 自己的模型选择器中选用；不替换默认模型。
6. 列表显示“AIO · Codex”等卡片，提供“管理来源渠道”“更新模型入口”“撤回接入”。源上游管理仍在原渠道页完成。

新按钮与现有“添加到 AIO 网关”分开：前者是 AIO → 原生入口，后者是原生上游 → AIO 快照。

## 2. 推荐机制与取舍

推荐建立受控渠道绑定，复用同一进程内的网关路由管线。

Pi/OMP → 本地受控绑定入口 → 读取来源渠道当前候选 → 协议/模型/能力过滤 → 现有认证、模型映射、重试、限额和发送 → 一条请求记录。

| 方案 | 取舍 |
| --- | --- |
| 实时引用来源渠道（推荐） | 保留单一供应商/认证事实来源，来源调整作用于后续请求；需要将调用方与路由渠道分开。 |
| 复制来源供应商到 Pi/OMP | 初始实现较浅，但形成凭证和策略副本，不能满足持续统一管控。 |
| 原生节点直接指向 /codex 等旧 URL | 可复用旧接口，但当前会把流量识别为 Codex，无法准确保留 Pi/OMP 统计与会话边界。 |
| 让 Pi/OMP 上游 HTTP 回调本机旧渠道 | 多一层循环风险、超时和双重统计；本任务不采用。 |

不改变现有 Pi/OMP 自有上游的“同客户端 + 同协议”约束；跨渠道仅由新增、已发布的绑定显式授权。

## 3. 身份与网关边界

将以下维度显式分开，具体字段名称在实现时按现有层次定稿：

| 维度 | 所有权 |
| --- | --- |
| consumerCli | 真实 Pi/OMP 调用方、前端过滤、日志归属和原生请求语义。 |
| sourceChannel | Claude/Codex/Grok/Gemini 来源池、当前工作模式、上游顺序及来源认证/适配策略。 |
| wireProtocol | 实际传输、输入鉴权剥离、错误返回形状和用量解析依据。 |
| bindingId | 后端拥有的目标/来源/协议/已发布模型绑定，支持撤回和审计。 |
| actualProviderId / UUID | 实际上游身份，继续用于熔断、额度和费用归属。 |

拟议本地入口为 /{consumer}/_aio/channel/{bindingId}/…，协议由绑定确定，后缀依现有生成器规则使用 /v1、/v1beta 或 Anthropic 根路径。最终路径以路由测试确定，不能复用存在冲突的旧匹配规则。

- 后端按绑定确定来源和允许模型，拒绝调用方任意覆盖来源、未发布模型、跨来源 forced-provider、无效/撤回绑定。
- 原生配置只含回环地址、占位凭证和白名单模型字段；来源的真实 API Key/OAuth 令牌只在后端认证管线加载。
- 只允许已批准的推理端点和方法；不借此开放任意管理、登录、文件或代理接口。已有本地监听/访问策略仍生效。
- 复用公共候选门禁、attempt、取消、deadline、模型映射、熔断、限额及插件执行；一次请求不再走第二套 HTTP 网关。
- 来源认证适配和调用方特有行为分别审计。不能为了使用 Codex OAuth 就把整条 Pi 请求伪装成 Codex，或套用全部 Codex 会话/文件配置行为。
- 会话键隔离 consumer + source + binding + 原始 session，避免与真实 Codex/Claude 会话或另一绑定相撞；供应商健康和额度仍按实际供应商共享。
- 前端及持久化日志增加可选来源渠道/绑定信息，旧记录保持兼容；调用方统计仍为 Pi/OMP，来源维度作为同一记录的筛选或分组，不重复计费。

## 4. 协议、认证与模型目录

首期四类来源矩阵（Gemini 已由用户确认加入，支持边界已获审核确认）：

| 来源渠道 | 入站原生协议 | 需要验证的重点 |
| --- | --- | --- |
| Claude Code | anthropic-messages | API Key 与现有 Claude 认证/消息适配的边界。 |
| Codex | openai-responses | 直接 API Key 和现有 ChatGPT/OAuth 适配；流式工具调用及模型映射。 |
| Grok | openai-completions / openai-responses | 双协议独立声明与选择，现有 OAuth/认证管线兼容性。 |
| Gemini | google-generative-ai | 标准 API Key 为基础路径；受支持的企业 Code Assist OAuth 需分别验证资格、包装/解包和 Google 用量语义；退役个人 OAuth 排除。 |

矩阵表示计划验证范围，不是已支持声明。某认证组合在来源渠道未实现时不凭空增加登录能力；已有且仍受支持的组合必须验证复用，失败应记录并返回范围审核。官方公告中的企业产品支持不直接等同于当前 AIO 的适配已兼容。

### 4.1 Gemini / Antigravity 支持边界

核查日期 2026-09-26；官方时间线、固定版本源码和本地证据见 research/gemini-antigravity-support.md。

| 来源认证路径 | 新接入流程处理 | 证据与限制 |
| --- | --- | --- |
| Gemini 标准 API Key / 兼容 API 上游 | 首期基础路径，使用 AIO 已有认证与协议验证；不复制 Key。 | 官方仍保留付费 API 访问；不把个人 Code Assist 的退役范围扩张到所有 Gemini API。免费 API 配额和其他平台资格按各自规则核实。 |
| Code Assist Standard / Enterprise | 保留为有条件验证路径，资格与适配兼容均成立后才加入候选。 | 不能仅凭一个 Google token 判断许可；当前 AIO 适配是否覆盖对应企业访问仍需验证。 |
| 个人免费 Code Assist / Google AI Pro、Ultra 旧 OAuth | 标明 2026-06-18 退役和迁移信息，不新增此类绑定候选。 | 禁止用仍存在的 SDK 代码、旧 README 或 token 刷新成功代替服务资格证据。 |
| 资格未知的旧 Gemini OAuth | 显示“需核实许可”，不计入可用候选，不诱导重新登录旧个人路径。 | 只能依据经过授权取得的服务/许可元数据或明确验证结果判断，不能根据邮箱域名、token/key 外观猜测。 |
| Antigravity | 不列为当前可接入来源；单列后续独立适配。 | 当前 AIO 没有该渠道/认证注册；不能只重命名 Gemini，也不能假设 OMP 原生 OAuth 可直接迁入 AIO。 |

两个消费端均发布标准 google-generative-ai 节点。Pi 0.71.0 同时移除了 google-gemini-cli 和 google-antigravity 内置供应商；本方案不依赖恢复这些内置项。OMP 18.3.2 保留两种原生 OAuth 实现，但它们的账号与配额不因此成为 AIO 的现成来源。

候选准入结果至少区分协议/模型不兼容、认证缺失、资格退役、资格待核实和适配待验证，并保留判断依据及复核时间。预览、确认和请求选源统一使用准入规则；来源或资格状态变化后重新检查，不能用已发布快照绕过。当前没有可靠元数据时如实返回待核实，不新增偷偷调用账号/计费接口的探测。

本任务的限制作用于新增渠道绑定；不删除或改写原 Gemini 账号与全局登录功能。若实施时发现原渠道也必须修复退役登录流程，记录为独立修复范围再审核。

### 4.2 模型目录与发布

模型目录复用来源模型列表、模型映射和现有能力信息，但 provider_models 目前没有覆盖原生发布所需全部字段。[E8] 不把模型名称、发现接口返回 ID 或协议名称当成完整能力证明。

- 以来源渠道的对外请求模型 ID 建立显式发布清单，保留真实远端模型 ID 的映射归属；同名模型不能仅靠显示名合并。
- 为候选供应商补充版本绑定的能力声明；Pi/OMP 不同的推理/工具限制沿用原生模型验证器。
- 目录来自当前可用池，可展示不完整项并明确补齐内容；仅有完整兼容候选的模型可发布。
- 请求时重新使用来源当前候选顺序，并过滤协议、模型及已发布能力。来源新增供应商不自动继承其他供应商的能力证据。
- 来源排序、启停、凭证轮换按现有规则作用于后续请求；新模型、端口、能力或协议改变使入口提示需更新，不静默改原生文件。新请求不使用已禁用候选；已发送请求沿用现有取消/完成规则。
- 所有候选失效时返回可诊断的本地错误；不退回 Pi/OMP 自有上游池或另一来源渠道。

## 5. 绑定、所有权与原子写入

当前 native_gateway_manifests 的主键为 target + protocol，无法同时拥有 Codex Responses 和 Grok Responses 两个独立来源。[E6] 不直接重定义旧主键的业务语义。

建议新增渠道绑定及其发布意图/所有权存储，逻辑唯一键为 targetId + sourceChannel + protocol，稳定 binding ID（SHA-256(targetId:sourceChannel:protocol)，64 位十六进制）；保存模型发布快照、节点键/摘要、revision、状态和恢复信息，不保存上游凭证。

- 新节点键包含来源和协议，例如 aio-channel-codex-openai-responses。前缀仅作命名，精确 manifest 才是所有权证据。
- 旧独立网关 manifest 保留；原生列表的“托管节点”投影同时识别旧入口与新渠道绑定，禁止普通编辑覆盖托管节点。
- preview 绑定目标 revision、来源目录/策略 revision、既有绑定 revision；confirm 加目标锁后重新检查，来源漂移返回冲突并重新预览。
- 同一目标一次多选：先预验证全部节点，再一次文件变更；沿用持久化意图 → 文件 CAS/原子替换 → 数据库完成 → 故障恢复。不得出现部分来源悄悄成功。
- OMP 继续显式 auth=apiKey；占位凭证仅作本地接入，不导入 native auth stores。
- 同名用户节点、外部修改、损坏文件、只读目标不得覆盖；仅撤回摘要仍匹配的精确节点。冲突时明确指出未撤回项，不能返回整体成功。
- 撤回绑定不删除来源上游/模型，其他目标和绑定继续生效；原生默认引用若由用户手工设置，只提示用户调整。
- 增量 schema 迁移需跟随实现时最新版本号。现有 portable/share 不足以表达该设备本地绑定时明确拒绝对应导出/替换，不悄悄遗漏；本期不扩大远程迁移能力。

## 6. 拟议接口与界面复用

新增服务族（名称待实现按 registry 统一）：来源渠道/模型能力查询、绑定列表、接入/更新预览、确认、撤回预览/确认。查询响应只返回摘要和已验证能力，不返回真实凭证。

- 扩展 existing native gateway app/domain 层，与 native provider 档案导入分离 DTO。
- 复用 NativeTargetPicker、Card、Dialog、Button 和现有预览/确认交互；一个接入弹窗供两个页签使用。
- 所有异步结果绑定 client/target/revision；切换渠道、目录或 Profile 后丢弃旧结果。
- IPC 通过命令注册表生成 bindings；前端 service/query 同步校验目标身份并正确失效缓存。

## 7. 兼容性与回退

上线前验证原有四渠道、Pi/OMP 自有池与原生配置不变。若新入口功能需回退，先提供精确撤回/停用绑定流程；保留冲突与恢复证据，不删除其他文件或强行回滚数据库。

最先做网关纵向验证：使用隔离 Pi/OMP 客户端，经新绑定进入 Codex 和 Claude 来源池，证明真实调用方身份、认证适配、重试与单次统计成立，再铺开矩阵和 UI。若此验证证明必须扩大协议转换/认证重构，暂停该扩展并提交具体证据给用户，不能以“只加按钮”掩盖范围变化。

## 批量默认值补充

候选选择器改为独立多选组件，批量追加且去重，不替换当前草稿。完整模型可折叠查看参数；待补充项展开。只读发现保留来源优先级与路由检查，采用精确协议/provider/model ID 的版本化公开模型目录补充缺失元数据。已知支持等级中自动选择默认值，并显示为可编辑建议。

## CLI 更新设计补充（用户已批准）

采用只读检查与主动执行分离的两个 IPC 命令，后端一次性短期计划固定确认的版本/方式/目录。npm/Bun 保持原安装目录，OMP 独立程序使用官方 Release + SHA256 校验后原子替换。执行前重查安装状态，进程/下载有时限与大小限制，用户取消和页面轮询不会启动升级。旧 Pi 包已停用（官方 npm 明确 deprecated），需要手动迁移，最新版本查询使用维护中的新包。详细计划见 research/cli-updates-plan.md。
