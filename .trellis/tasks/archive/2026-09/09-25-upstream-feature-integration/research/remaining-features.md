### Product decision gates and safety constraints

1. **Billing source gate (`e2d03792`).** Upstream adds `CodexPriorityBillingSource` with default `Requested` (`upstream src-tauri/src/infra/settings/types.rs:50-64,227-236`) and passes it to service-tier resolution (`upstream src-tauri/src/gateway/proxy/handler/failover_loop/prepare/codex_service_tier.rs:169-184`). Fork currently resolves priority from the response/actual tier (`src-tauri/src/gateway/proxy/handler/failover_loop/prepare/codex_service_tier.rs:176-184` hard-codes `"actual"`). A request with `priority` but response `default` changes from ordinary billing to priority billing under upstream defaults. Recommended fork-safe option: add the selector but retain `Actual` as the migration/default choice; selecting upstream's `Requested` behavior requires explicit product approval and settings migration tests.
2. **Generic invalid-request rectifier gate (`e2d03792`).** Upstream broadens `thinking_signature_rectifier::detect_trigger` to match every generic “invalid request” (`upstream src-tauri/src/gateway/thinking_signature_rectifier.rs:64-69`); fork intentionally requires thinking/signature/redacted context and tests unrelated generic errors as `None` (`src-tauri/src/gateway/thinking_signature_rectifier.rs:65-71`, `tests.rs:66-70`). Recommended option is to preserve the narrow guard and add only the new rectifier registry/response-input normalization. Broad matching would change retries and could alter ordinary 400 handling; it requires explicit approval plus strict route-level regression tests.
3. **Mandatory firewall boundaries.** Any adaptation must preserve strict Codex phased-message validation, pre-commit stream recovery, CX2CC one-hop/self-loop guards, configured retry/failover attempt budgets, settings lock/rollback ownership, OAuth secret redaction, and immutable release source resolution. Upstream-origin defects discovered while carrying a patch remain out of this integration task and need separate follow-up tasks.

## Recommended sequencing

1. Land low-conflict, contract-aligned infrastructure first: Claude backup refresh (`def1060c`) and OAuth configured-proxy routing (`3bd9bb59`), with focused Rust tests.
2. Adapt audit fallback (`3758d8e8`) while preserving registry/Windows execution, then run self-tests and fail-closed checks.
3. Port cost correctness in two isolated slices: overflow-safe aggregation (`ab83c23f`) and compatible missing-output-rate/priority fallback from `85253db0`; keep incremental log refresh unchanged.
4. Add provider UI locate behavior (`37319565`) and probe dialog/model+prompt (`b3343335` series), with frontend tests and generated-binding checks only where IPC payloads change.
5. Resolve the two `e2d03792` decision gates (billing source and generic rectifier trigger) before implementing any rectifier/settings migration. Integrate only selected, contract-tested rectifiers.
6. Run full Rust/frontend quality gates, then verify merge ancestry and origin-only repository operations. Do not include unrelated upstream defects or release metadata.
