# 修复 CX2CC 路由与 GPT-5.6 配置

## Goal

让 CX2CC 作为既有协议路由时保持单一、可预测的数据流，并同步当前
Claude/Codex 模型能力：补齐与 `upstream/main` 的相关差异，避免 CX2CC
二次模型路由、固定思考强度以及本机 AIO 网关来源被误判为递归回环。

## Background

- 用户观察到 CX2CC 设置页的思考强度与 GPT-5.6 新模型能力不一致。
- 供应商选择界面缺少 GPT-5.6。
- CX2CC 未按实际 GPT 型号提供对应的上下文窗口能力，可能使调用方采用错误的
  压缩阈值并触发异常压缩行为。
- CX2CC 本身已经承担协议路由职责，不应再叠加配置模型路由。
- CX2CC 的思考配置应透传调用方请求，而不是无条件写入固定值。
- 当 CX2CC 来源选择“当前 AIO 服务 Codex 网关（跟随当前分流）”时，现有
  网关回环保护会误触发；真正会形成递归调用的配置仍必须被阻断。
- 本任务明确允许对 `upstream/main` 做 Claude/CX2CC 相关差异审计，并由实现者
  根据代码证据判断同一根因下的必要修复范围。

## Requirements

- R1：审计当前分支与最新 `upstream/main` 中 Claude、CX2CC、Codex 模型目录、
  思考能力和网关回环相关差异；只移植与本任务目标相关且未合入的上游变化。
- R2：CX2CC 请求不得再次套用通用“配置模型路由”；发送给实际来源供应商的
  模型应遵守 CX2CC 协议路由自身的契约。
- R3：CX2CC 不得用设置页默认值覆盖请求中的思考配置；受支持的调用方思考参数
  应端到端透传。缺省请求也不得从旧持久化字段注入固定 effort。
- R4：模型能力与选择目录应覆盖项目当前支持的 GPT-5.6 型号，并在 CX2CC
  思考强度设置和供应商模型选择中保持一致；不能只补 UI 文案而遗漏运行时能力。
- R5：CX2CC 选择当前 AIO Codex 网关并跟随当前分流属于合法内部入口，不得被
  回环保护误判；直接或间接重新进入同一 CX2CC 路径的真实递归仍须失败关闭。
- R6：检查与上述链路共享同一数据源、能力表或判定函数的相关问题，并纳入
  必要的一致性修复和回归测试；无关重构与 upstream 原生缺陷不在本任务实施范围。
- R7：保留普通 Codex、Claude 供应商及其他协议桥接的既有路由、鉴权、故障转移
  和请求参数行为。
- R8：CX2CC 必须按最终实际 GPT 模型解析并提供正确的上下文窗口能力，使调用方
  的压缩决策与该模型真实容量一致。优先复用可验证的模型能力目录；对目录未知、
  自定义或未来模型必须有明确、兼容且不会冒充已确认容量的回退行为。

## Acceptance Criteria

- [x] 有可审计的 upstream 差异清单，明确“移植、已有、fork 特有、范围外”分类。
- [x] CX2CC 路径不会命中通用配置模型路由，且测试证明普通非 CX2CC 路径不回归。
- [x] 请求显式携带的思考配置经 CX2CC 转译后保持语义等价，不被固定设置覆盖。
- [x] GPT-5.6 在适用的供应商选择与 CX2CC 配置界面可选，支持的思考强度与后端
      能力/请求转换一致，并覆盖旧模型兼容测试。
- [x] CX2CC 对不同 GPT 模型暴露/应用各自的上下文窗口；模型切换后压缩阈值随之
      更新，已知、未知和自定义模型均有回归测试，且不会把一个型号的容量套给另一个。
- [x] 选择当前 AIO Codex 网关的合法 CX2CC 场景可以完成请求；真实自引用或递归
      配置仍被稳定拒绝，并有正反回归测试。
- [x] Claude/CX2CC 相关 upstream 必要变化均已评估，任何未移植项都有明确理由。
- [x] 相关前端单测、TypeScript 类型检查、Rust 定向测试及受影响的完整质量门通过。

## Notes

- 本任务是跨前端、配置、协议转换和网关路由的复杂任务，实施前必须补齐
  `design.md`、`implement.md`、`implement.jsonl` 与 `check.jsonl`。
- upstream 工作保持集成性质：仅解决具体差异和 fork 决策，不修复 pinned
  upstream 本身已有且与合并无关的缺陷。
