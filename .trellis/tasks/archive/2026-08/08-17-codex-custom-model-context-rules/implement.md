## Risk And Rollback Points

- `settings/persistence.rs` raw migration and repair durability are the first gate. Stop if a legacy true value can be cleared or a failed repair can be reported as success.
- `codex_model_catalog/managed.rs` owner v3 and original binding recovery have the largest blast radius. Stop on any test that loses a user catalog path, unknown JSON field or external winner.
- Candidate GET must stay side-effect free. A directory/config write during GET or prepare blocks frontend integration.
- Stabilize backend DTOs before generated bindings and frontend parallel work converge; avoid concurrent edits to generated files.
- No packaging starts before focused and full checks are green. No release starts before merged SHA CI succeeds.
- Never reuse/move a release tag, overwrite published assets, force-push `release-channels`, or publish from a mutable branch ref.
