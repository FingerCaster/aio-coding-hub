# Pi / OMP 原生管理与 AIO 网关接入

## 目标与状态

重新调研 Pi 与 Oh My Pi（OMP）的原生配置、模型及请求契约，参考 CCS，形成 AIO Coding Hub 的新接入方案。首期同时交付原生管理和 AIO 网关能力，用户可以保留原生供应商并主动选择独立的 AIO 入口。

用户于 2026-09-26 明确要求“开始吧”，任务已进入 in_progress。实施及运行时验收进度见 [实施验证记录](research/implementation-validation.md)；计划与验收条件本身不代表测试已通过。

## 已确认产品决策

- D1：首期同时支持原生供应商及模型管理、AIO 网关路由、重试和统计，不将网关留到后续版本。
- D2：网关采用独立 AIO 供应商入口，与原生供应商并存；不自动修改默认供应商、默认模型或正在运行的会话。
- D3：参考 D:/UGit/cc-switch-main 的接入方式，并按用户授权克隆 Pi / OMP 开源仓库核对真实契约。
- D4：旧 pi-omp-cli-management 方案已弃用。以当前 origin/main 基线重新设计，不恢复旧实现作为设计基线。

以上决策均于 2026-09-26 确认。仓库、版本、不可变提交及验证边界见 [来源基线](research/source-baselines.md)。

## 调研结论与依据

- [CCS 参考](research/ccs-reference.md)：借鉴显式供应商节点同步、累加式启用、归档与原生配置分离；其 Pi 原生管理不能直接替代 AIO 网关设计。
- [原生 CLI 契约](research/native-cli-contracts.md)：Pi 与 OMP 分别适配目录、格式、认证和模型能力，不能共用一个假定兼容的配置序列化器。
- [AIO 接入点](research/aio-integration-map.md)：沿用现有网关执行链，把客户端身份与线路协议分开，避免把 Pi / OMP 伪装成 Codex 等现有 CLI。
- 架构、数据归属与失败恢复见 [设计方案](design.md)；实施依赖及验证顺序见 [实施计划](implement.md)。

## 功能需求

| 编号 | 需求 |
| --- | --- |
| R01 | Pi 与 OMP 各为独立渠道；入口与操作按真实能力展示，协议不膨胀成多个 CLI 渠道。 |
| R02 | 支持显式选择默认目录、自定义目录及 OMP profile，读写目标可见且可区分。 |
| R03 | 原生供应商支持查看、新增、编辑、应用、移除和删除归档；是否启用以目标文件中显式节点存在为准，内置供应商同名节点同样处理。 |
| R04 | 原生配置外部修改可刷新并同步归档；进入 AIO 上游池必须显式预览及导入，不因刷新原生配置而改变运行中的网关。 |
| R05 | 模型能力与覆盖项使用各自原生契约，保留未知字段，不按模型名称前缀猜测能力或复制完整内置目录。 |
| R06 | 文件损坏、不可识别格式、目标歧义、外部修改和写入失败均有明确冲突或恢复行为；不得回退为空配置后覆盖原文件。 |
| R07 | 两个 CLI 首期均纳入 anthropic-messages、openai-completions、openai-responses、google-generative-ai 四种 HTTP/SSE 网关协议验收。 |
| R08 | 复用 AIO 路由、门控、配额、重试、熔断与失败切换；候选需同时匹配客户端、协议和已声明模型，不能跨协议盲目重试。 |
| R09 | 生成的独立 AIO 入口只指向本地网关，使用专用生成字段；不得泄露上游密钥或残留会绕过网关的地址、headers、发现或传输设置。 |
| R10 | 入口应用、更新、移除应幂等，保护同名非托管节点及用户外部编辑，部分失败可定位和恢复。 |
| R11 | 不读取或修改原生登录文件、OAuth 数据库，不执行导入值中的环境变量或命令表达式；网关凭证由用户明确配置到 AIO。 |
| R12 | 日志、用量及价格归属保留真实 Pi / OMP 身份、协议和最终模型，复用现有 attempt 及 usage 语义。 |
| R13 | 按各协议能力验证工具调用、思考、图像、取消、SSE 和非流式请求；已向下游提交响应后不重放请求。 |
| R14 | UI 区分原生节点存在、网关入口已配置、监听器就绪和实际流量经过网关，不把写配置宣称为当前会话已切换。 |
| R15 | 兼容现有四个 CLI、数据库迁移、模型路由及共享契约；不能完整承载新增字段的共享功能须明确禁用，不能静默丢失语义。 |

## 首期范围

首期包含两个原生适配器、供应商及模型编辑、外部同步、显式网关导入、四种协议网关适配、独立入口生命周期、路由与重试、日志及用量、必要的迁移和回归验证。Windows 是当前工作环境；声称支持的 macOS / Linux 路径和权限行为也必须具备相应验证依据。

原生 OAuth 登录、特殊云认证、WebSocket、OMP pi-native 传输、扩展自定义协议、内置目录复制、MCP / skills / prompts / sessions 管理、项目级改写、WSL 及 CLI 自动安装更新不在本期范围。用户仍可在原生 CLI 使用这些能力；AIO 不将其错误转换为通用网关 API-key 请求。

| --- | --- | --- |

| A02 | 默认与自定义目标、OMP profile、YAML 文件优先级及旧 JSON 状态均有夹具和路径测试，歧义不能静默选错目标。 | R02、R06 |
| A03 | 原生显式节点的增加、编辑、应用、移除、删除归档及外部刷新符合统一语义；包括内置名称节点和已停用归档。 | R03 |
| A04 | 导入预览准确表达模型、协议、地址及覆盖差异；确认后生成独立上游快照，后续原生刷新不自动更新它。 | R04、R05 |
| A05 | 未知字段及非目标节点在读写后保留；损坏文件、并发变更和补偿冲突不会触发空覆盖或覆盖他人修改。 | R05、R06 |
| A06 | 固定版本真实 Pi 与 OMP 分别通过四种协议的 CLI → AIO → 本地模拟上游测试；各协议支持的工具、思考、图像及流式能力有证据。 | R07、R13 |
| A07 | 同客户端、同协议且模型兼容的两个上游可失败切换；不兼容候选零上游请求，且不消耗 attempt 预算或损伤健康状态。 | R08 |
| A08 | 生成入口无真实上游密钥、地址及绕过设置；重复应用结果一致，仅安全移除当前仍归 AIO 所有且未外改的节点。 | R09、R10 |
| A09 | 名称碰撞、外部编辑、端口变化及数据库 / 文件 / manifest 各阶段失败都有明确状态和条件补偿测试。 | R06、R10 |
| A10 | AIO 管理操作前后，原生认证文件、数据库与默认设置内容和修改时间不变；命令表达式不执行，日志及导出不暴露密钥。 | R11 |
| A11 | 捕获请求与 AIO 日志中的客户端、协议、最终模型和 attempt 对应；用量、缓存及价格遵循现有契约，原生直连不伪造网关统计。 | R12 |
| A12 | SSE 错误、正常结束、非流式失败、客户端取消和已提交响应边界正确，不伪报成功或重放已提交请求。 | R13 |
| A13 | 迁移后现有四个 CLI 的路由、认证及模型行为保持兼容，覆盖 Grok 双协议及 Codex 受管模型功能。 | R15 |
| A14 | 新增字段在允许的共享往返中完整保留；不支持的组合有明确禁用反馈；独立 AIO 入口不改变原生默认或当前会话。 | R10、R15 |
