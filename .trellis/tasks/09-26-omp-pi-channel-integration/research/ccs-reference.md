## 不直接照搬的部分

1. CCS 此基线有 Pi 原生管理，没有 OMP 的对应接入模块；搜索到 oh-my-pi 仅为资料提及。OMP 必须单独按官方源码实现。
2. CCS 的 Pi 路径明确不承担代理、路由与 failover；用户已确认 AIO 首期要做这些，因此 CCS 不能提供网关方案。
3. CCS 的 JSON5 读取比 Pi 0.87.1 的 JSON.parse(stripJsonComments(...)) 更宽。不能让 AIO 保存 Pi 实际不接受的单引号、裸键或尾逗号。
4. “已启用”在 CCS Pi 表示节点存在。AIO 另有上游参与路由、监听器就绪和真实请求观测，必须分开命名。
5. 不能把 CCS 数据表直接搬进 AIO；AIO 已有 providers、路由规则、请求日志和用量计费，应保留这些能力的唯一运行时实现。
6. 原生节点可包含 apiKey / headers 的表达式。CCS 不执行它们，AIO 的列表同步和导入预览也不能执行；网关需要自己可用的明确凭证。

## 推荐借鉴范围

- 原生文件为“已加入 CLI”的事实来源，数据库保留未加入的档案。
- 精确 provider key，不模糊归并，不只导入非内置 ID。
- 未知字段透传；面向用户暴露常用字段和原文编辑。
- 目标节点读改写、边界内串行化、revision 检查和有条件补偿。
- 只读读取失败时保留已保存卡片，但显示状态未知并禁止成员关系写入。
- 将实际选择模型的行为交还 Pi / OMP；独立 AIO 入口也是一个原生 provider。
