# 第一组低风险可靠性修复

## Goal

在不改变网关真实请求重试、Provider 运行时门禁和遥测展示的前提下，修复五项低风险但可独立验证的可靠性问题，并在独立 worktree 通过完整质量门禁后合并到 `main`。

## Background

- 路由草稿当前固定从默认顺序开始，未采用该 CLI 已持久化的当前模式。
- `.github/workflows/sync-upstream.yml` 目前允许直接推送或自动合并，缺少人工审查门禁。
- Rust 数据库初始化会缓存失败结果，前端启动状态的先同步后订阅也存在漏事件窗口。
- 诊断数据会经过控制台、IPC、前端错误上报和 Rust 日志，当前各边界的脱敏规则不一致。
- 任务完成通知只依据前端会话状态，异步计时器可能在状态已变化后继续触发。

## Requirements

- R1：每个 CLI 的路由草稿只初始化一次；若持久化当前模式仍存在则默认选中该模式，否则选择默认顺序；异步查询不得覆盖用户已做的显式选择。
- R2：上游同步只能创建或更新 PR，禁止工作流直接推送目标分支或自动合并；冲突或未知合并状态必须失败闭合，并提供可在 CI 中执行的策略自检。
- R3：数据库初始化失败不得永久缓存，下一次启动重试必须重新初始化；前端必须先建立启动状态监听再同步快照，并忽略失效订阅或旧请求返回。
- R4：诊断文本、结构化值、URL、IPC 错误、前端错误和后端日志必须使用一致的失败闭合脱敏策略；遍历深度、节点数、字符串长度和总输出量必须有界。
- R5：任务完成通知触发前必须用后端活动请求快照复核同 CLI 是否仍有请求，并用世代标识阻止旧计时器触发；后端复核失败时不通知。

## Constraints

- 保留现有任务通知默认 30 秒静默期，不引入 Codex 特殊延迟。
- 不实现传输错误重试退避、Provider 全局启停门禁或 tokens/s 展示。
- 不改变真实网关路由、请求重试或供应商启停语义。
- 同步策略变更只约束本仓库 workflow；实际同步仍通过 PR 人工审查，不自动改写 `main`。
- 保留现有公共 API 和持久化格式，避免数据迁移。

## Acceptance Criteria

- [x] 五个子任务的针对性单元/集成测试全部通过。
- [x] `pnpm typecheck`、`pnpm lint`、格式/生成绑定检查及受影响 Rust 测试通过。
- [x] 同步策略自检能拒绝直接 push、自动 merge 和非失败闭合状态判断。
- [x] 诊断测试覆盖自由文本、嵌套对象、URL 凭据/查询、循环对象、异常 getter 和资源上限。
- [x] 启动失败后第二次重试确实重新进入初始化，且成功结果仍只初始化一次。
- [x] 通知测试覆盖后端仍活跃、快照失败、旧计时器和正常通知，并保持 30 秒默认值。
- [ ] 独立分支提交完成，最终质量审查通过后以非破坏方式合并到 `main`，不覆盖主 worktree 既有改动。

## Out Of Scope

- 传输错误重试退避。
- Provider 运行时全局启停门禁。
- tokens/s 遥测或任何新的 UI 展示。
- 自动合并同步 PR。
