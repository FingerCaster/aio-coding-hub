# Pi / OMP 接入 AIO 统一渠道

状态：用户于 2026-09-26 批准实施，开发与验收进行中。

## 目标

在 Pi 和 OMP 的供应商页面新增“从 AIO 渠道接入”：用户选择已有的 AIO 统一渠道和模型后，生成独立、可撤回的原生供应商入口。请求继续由 AIO 管理供应商选择、凭证、模型映射、重试、限额和统计。

用户原始要求：“增加一个导入 AIO 可接入渠道的方式，比如说接入 Codex、Claude Code、Grok 这种统一渠道，受 AIO 管控的。可以创建一个任务，交给我审核。”

2026-09-26 补充要求：用户同意加入 Gemini，并要求先核实 Gemini 与 Antigravity（反重力）的支持变化，再提交审核。支持边界核实后，用户已回复“可以 开始吧”。

## 审核摘要

### 已授权的体验补充（2026-09-26）

用户要求：从 AIO 渠道添加模型时，能够获取的模型、思考等级等能力自动获取；能够用下拉填写的字段使用下拉。此项直接纳入当前任务实施，无需再次审核。

- 打开模型能力编辑器后自动进行只读发现；模型 ID、容量、输入、工具、推理及思考等级只取明确返回或来源已保存的能力。
- 选择模型自动填入已知项；模型、输入、工具、推理、思考模式、档位映射与默认等级提供选择器，保留自定义 ID 与高级 JSON。
- 失败、刷新、迟到响应不得覆盖手动编辑、清空值、JSON 草稿或另一个目标的内容。
- 模型/思考路由改写或响应能力冲突时，保留候选，要求核对实际能力；不把远端 ID 能力误用到另一个请求模型。
- 发现不写 catalog、凭证、CLI 配置或绑定；保存与发布仍需用户确认并验证 revision。

本方案建议“实时引用渠道”：例如在 Pi 中添加“AIO · Codex”，使用 AIO 当前 Codex 渠道的上游池；AIO 调整供应商、凭证或排序后，后续请求遵循来源渠道当前规则。入口保存用户选择的模型清单，不自动扩大模型范围。

这里接入的是整个渠道，不是复制某一家上游的 URL/API Key。现有“原生供应商添加到 AIO 网关”是相反方向，保留原功能并区分文案。

首期范围包含用户已确认的 Claude Code、Codex、Grok、Gemini 四类来源渠道。Gemini 通过标准 google-generative-ai 协议接入 AIO；来源侧按实际 API/认证资格筛选，不依赖 Pi 已移除的内置订阅供应商。每个渠道按实际协议、认证和模型能力显示可接入或阻塞原因，不将“有供应商”直接当成“可用”。

Gemini 并非整体停止支持：Google 2026-05-19 公告明确，个人免费 Code Assist 与 Google AI Pro/Ultra 的旧 CLI 服务自 2026-06-18 停止，迁往 Antigravity；Standard/Enterprise 许可及公告列明的付费 API Key 访问继续保留。当前 AIO 没有 Antigravity 适配，不能把 Gemini 改名后宣称已支持。本次推荐保留 Gemini 标准 API 来源，对企业 OAuth 单独验证，将 Antigravity 作为独立后续适配候选，按已批准范围实施。详见 research/gemini-antigravity-support.md。

## 已确认背景

- 用户此前选择“独立 AIO 入口与原生供应商并存”，不自动改默认模型和已有会话。
- 现有 Pi/OMP 网关目录仅从自身客户端的供应商池生成，并要求直接 API Key 上游，不能直接代表其他统一渠道。[E1][E2]
- 现有导入接口是原生配置到 AIO 上游快照；新的方向是 AIO 统一渠道到 Pi/OMP 入口。[E3]
- AIO 已有按渠道选择活动上游、会话绑定及协议适配机制；真实客户端身份与来源渠道目前未独立建模。[E4][E5]
- Pi 0.87.1 的变更记录载明 0.71.0（2026-04-30）同时移除 Gemini CLI 和 Antigravity 内置支持，但标准 Google API 仍存在；OMP 18.3.2 仍保留两种 OAuth 实现，源码存在不证明账户现在可用。[E13][E14]
- 证据与代码定位见 research/code-evidence.md。依赖前置任务 09-26-omp-pi-channel-integration 的原生配置、网关和界面实现，本任务不替代其验收。

## 功能要求

| ID | 要求 |
| --- | --- |
| R1 | Pi/OMP 原生供应商工具栏提供“从 AIO 渠道接入”；AIO 网关视图提供同一流程入口。 |
| R2 | 弹窗按统一渠道展示名称、可用协议、当前可用上游数、已接入状态和不可接入原因；候选数量经过认证资格与兼容性过滤，不计入已退役或资格未知的旧 Gemini OAuth 候选；支持一次勾选多个渠道，目标固定为当前 Pi/OMP 目录或 OMP Profile。 |
| R3 | 用户选择渠道及显式模型，确认必要的模型能力，预览实际新增/更新的供应商、协议、模型和配置文件，再一次确认写入；取消不写文件。缺少模型/能力时给出补齐入口，不猜测能力。 |
| R4 | 接入后生成“AIO · Claude Code”“AIO · Codex”“AIO · Grok”“AIO · Gemini”等独立供应商；同一渠道有多协议时明确区分。标识稳定，重复接入更新已有绑定，不产生重复节点。 |
| R5 | 来源渠道仍拥有上游池及认证；不复制供应商记录，不把真实上游密钥或 OAuth 令牌写入 Pi/OMP。接入不要求用户重新输入 AIO 已持有的凭证。 |
| R6 | 后续请求使用来源渠道当时的工作模式、供应商启停/排序、模型映射、重试、熔断及限额等公共策略，同时满足所发布模型的协议和能力约束。禁用/删除的上游不能因旧入口继续使用；新增不兼容上游不能自动接流量。 |
| R7 | 已接入卡片标注“AIO 托管”和来源渠道，提供管理来源渠道、更新模型入口、撤回接入。监听器就绪、配置存在、实际请求成功分别展示，不把“已接入”写成“正在使用”。 |
| R8 | 请求记录保留真实调用方 Pi/OMP，并可查看来源渠道、模型和实际上游；复用同一计费/统计链，不因引用产生双重请求记录或重复费用。 |
| R9 | 目录/Profile 切换、配置损坏/只读、同名用户节点、外部修改及来源变化均给出具体结果；沿用精确节点所有权、版本检查、私有备份、原子写入和恢复。撤回只移除该目标内仍属 AIO 的节点。 |
| R10 | 保留原生供应商、现有 Pi/OMP 自有网关入口、默认模型和当前会话；来源渠道仍可被原生 Claude/Codex/Grok/Gemini 客户端正常使用。 |
| R11 | Gemini 标准 API、企业 Code Assist OAuth、已退役个人 Code Assist OAuth 分别判断；不能根据邮箱、是否有 token 或 key 字符串猜测套餐。资格未知的旧 OAuth 显示“需核实许可”，已退役的显示迁移提示并禁止通过新流程接入。当前不提供 Antigravity 可选来源，不覆盖旧账号或将其自动转换为另一产品。 |

## 范围与限制

- 新流程是本机 AIO 统一渠道的接入管理，不自动安装、登录、启动或接管各 CLI。
- 复用现有且仍受支持的源渠道 API Key/OAuth 认证适配器；不能无提示退化为仅 API Key。Gemini 企业 OAuth 只有许可资格和 AIO 适配均验证通过后才可用；个人免费/Pro/Ultra 旧 OAuth 不列为成功通路，未知资格保持待核实。其他未通过组合明确阻塞，范围变化返回审核。
- Google 的个人 Code Assist 迁移公告不等于 Gemini 模型/API 或所有免费 API 配额退役；本任务不据此封禁全部 Gemini，也不承诺未核实的免费 API 或任意 Vertex/企业接口可直接复用。
- Antigravity 的独立渠道、认证、配额、协议和实际账户验证属于后续单独适配；本次只记录依赖与阻塞原因，不借 OMP 原生实现或本机 agy 可运行来宣称 AIO 已接通。
- 原生文件中的模型清单是显式发布快照；后台供应商调度动态生效，新增模型或能力变化通过“更新入口”预览确认。
- 首期不新增任意协议翻译，不支持以 Pi/OMP 渠道引用另一 Pi/OMP 渠道，不新增递归/多跳桥接。已有 CX2CC 等桥接候选先标注不可接入，后续可单独扩展。
- 本轮实施本地代码、隔离验证与 Windows 测试包；不写真实用户 CLI 配置、不创建远程 Issue/PR，不自动提交或发布。

## 验收标准

| 验收 | 对应要求 | 可验证结果 |
| --- | --- | --- |
| A1 | R1–R3 | 两页均可打开同一接入流程；四类来源有明确可用/不可用原因；无供应商、监听未启动、能力缺失时不误报可接入；取消无副作用。 |
| A2 | R3–R5 | 一次选择 Codex 和 Claude Code 后，当前目标产生独立可识别节点；不增加上游副本、不暴露凭证；再次接入幂等。 |
| A3 | R5–R6 | 来源渠道切换排序/工作模式、轮换凭证、禁用上游后，下一次请求按现有规则生效；原生文件不需要重新复制凭证。 |
| A4 | R6 | 失败时只在来源渠道的兼容候选中按公共预算重试；跨来源串流量、协议不符、能力不符和已禁用候选都不能被尝试。 |
| A5 | R7–R9 | 日志显示“Pi → Codex → 实际上游”或“OMP → Claude Code → 实际上游”；流式/非流式、取消和失败用量不重复记账，会话不串用。 |
| A6 | R9–R10 | Pi 默认/自定义目录和 OMP Profile 隔离；外部改动与同名用户节点不会被覆盖；撤回不影响其他渠道入口、原生节点、默认模型或会话。 |
| A7 | R5–R6、R11 | 两个真实 CLI 使用隔离配置跑通审核范围内的协议矩阵，Gemini 基础路径为标准 API；仍受支持的 OAuth 适配与许可条件分别记录证据，mock 通过不写成真实账号可用。 |
| A8 | R1–R11 | 原生 CRUD、旧独立网关及原有四渠道的路由/统计回归通过；迁移、失败恢复和导入导出边界有测试。 |
| A9 | R2、R11 | 覆盖 Gemini 标准 API、企业 OAuth、退役个人 OAuth、未知资格、混合候选池及资格变化；不能仅因日期到期禁用企业许可，不能因持有旧 token 放行个人路径；Pi 发布配置不出现已移除的内置 provider，Antigravity 不被当成 Gemini 别名。 |

## 已确认决策

此前方案方向和加入 Gemini 已获用户同意；用户已确认核实后的支持边界：四类来源都纳入，Gemini 标准 API 为基础路径、受支持企业 OAuth 经验证后开放，已退役个人路径不接入；Antigravity 不冒充现有渠道，单列后续适配候选。若希望本期同时新增 Antigravity 来源，需要扩展独立认证与网关适配设计后再审核。

审核入口为本文件；技术细节见 design.md，实施与验证清单见 implement.md。任务已启动；实际验证证据写入 research/validation.md。

## 批量导入体验补充（2026-09-26，用户已授权）

- 模型搜索、多选、全选当前结果、清空选择和一次批量添加；已有模型不重复添加。
- 已知模型自动填充上下文、输出上限、输入、工具及思考模式/等级/默认值，仍可逐项修改。
- 优先用户保存声明和显式上游能力，缺失值可由带来源与版本的精确模型目录补齐；不按名字前缀猜测。
- 完整模型以摘要展示，按需展开修改；未知和路由改写模型明确提示待核对。

## 已批准范围扩展：CLI 主动安装与升级

用户于 2026-09-27 批准 Pi/OMP 自动检查新版本、下载安装和一键升级，并明确禁止自动升级。进入页面及前台定时检查只提示；安装和升级必须由用户点击并确认。展示当前/最新版本和安装方式；未安装可安装，失败可重试，未知安装方式保持手动处理。保留原生配置和当前安装位置。执行计划见 research/cli-updates-plan.md。
